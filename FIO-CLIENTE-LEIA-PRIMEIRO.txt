FIO — acesso do cliente, identidade da barbearia e recuperação de sessão

Base: FIO-PARA-CORRIGIR-20260926-114943.zip, enviado em 26/09/2026.

COMO APLICAR
1. Guarde uma cópia da pasta finalfio1 como backup.
2. Extraia o conteúdo deste ZIP na raiz de finalfio1, mantendo src, server,
   public e tests. Aceite substituir os arquivos. Não substitua a pasta inteira.
3. Nenhum arquivo antigo precisa ser excluído. Nenhuma migração nova é necessária.
4. No PowerShell dentro de finalfio1:
   npm run verify
   if ($LASTEXITCODE -ne 0) { throw "Validação falhou. Pare aqui." }
   git diff --check
   if ($LASTEXITCODE -ne 0) { throw "Revise o diff antes de publicar." }
5. Depois das verificações:
   npx vercel --prod
6. Reabra https://usefio.vercel.app e faça login novamente se solicitado.

ALTERAÇÕES
- Links antigos com shop, sem audience, passam a identificar o acesso de cliente.
- Contexto da barbearia preservado nas rotas de cliente, callbacks de Google e e-mail.
- Cadastro de cliente sem contexto não cai na criação de barbearia.
- Falha ao resolver a barbearia informa erro, sem escolher silenciosamente outra.
- Nome/logo no acesso, cadastro complementar, cabeçalho mobile e chat do cliente.
- Plano SaaS não aparece no cabeçalho do cliente. Regras e cobrança não alteradas.
- Logo também aceita o caminho de imagem já salvo nos dados da barbearia.
- API renova a sessão uma vez após AUTH_REQUIRED (401), compartilhando a renovação
  entre chamadas concorrentes. Se continuar inválida, encerra só a sessão local.
- Não repete pagamentos/agendamentos após erro de rede ou autorização 403.
- Service worker tem resposta offline válida se não existir cópia da página.

VERIFICAÇÃO EXECUTADA
- TypeScript, 199 testes e build aprovados.
- 6 testes de navegador: celular 390x844 e computador 1440x1000.
- Fluxo: portal > login de cliente > criar conta > entrar > completar perfil > painel
  > chat > recarregar. Callback Google e e-mail mantém audience=client e shop.
- Serviços de autenticação, dados e IA simulados nos testes de navegador.
- Revisão visual do login e chat. Não houve alteração do teclado/layout geral.

LIMITES E TESTE REAL
Não houve deploy nem acesso às chaves ou ao banco real. A origem exata do 401 em
produção não pode ser confirmada só pelos prints. Este pacote corrige a ausência
de recuperação da sessão, mas não substitui configurações válidas do servidor.
Teste o link real em janela anônima, criando um cliente e verificando nome/logo,
agendamento e resposta da IA. Se o 401 persistir após novo login, confira se
VITE_SUPABASE_URL e SUPABASE_URL apontam para o mesmo projeto e se cada chave
corresponde a ele; não envie chaves no chat. O Google e CAPTCHA reais dependem
das configurações existentes. Não foi realizado pagamento real.
